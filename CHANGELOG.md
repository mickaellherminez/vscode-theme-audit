## [0.2.0] - 2026-11-24

### Added
- `--format text|json|markdown` selects the report renderer, with text as the default and `--json` kept as an alias for `--format json`. The Markdown report and `markdownReport()` API give the complete totals, failed checks, confused pairs, configuration and ignored reasons, warnings, errors and strict variety. Details are limited to 60,000 UTF-8 bytes with an explicit truncation notice; theme data is escaped and mentions are neutralized. Contradictory format options fail with exit code 2 ([#18](https://github.com/mickaellherminez/vscode-theme-audit/issues/18)).
- A JavaScript GitHub Action with its engine and dependencies bundled, running with Node.js 24: inputs `path`, `strict`, `config`; a Markdown job summary even on audit failures; outputs `report-path` and `exit-code`. Its demonstration workflow uses the existing test themes in this repository on Linux, Windows and macOS, without a separate example repository. A separate Ubuntu workflow calls the public action at a reviewed full commit SHA from a checkout containing only fixtures and report assertions, verifying download, success and expected failures. CI checks the shipped bundle against the sources and runs it from an isolated folder without npm dependencies. The README and action guide explain usage, fixed commit references, removal and the owner's Marketplace publication steps. Live workflow results and the Marketplace listing require validation on GitHub; the source change alone does not establish them ([#18](https://github.com/mickaellherminez/vscode-theme-audit/issues/18)).
- A configuration file, `.vscode-theme-audit.json` in the extension folder (also read inside a `.vsix`), or `--config <file>` for every input: the four reference thresholds (`text` 4.5, `enhancedText` 7, `nonText` 3, `deltaE2000` 7), and checks or pairs to ignore, each with a required reason. Ignored checks and pairs stay in the report, marked `IGNORED` with their reason (`ignored` in the JSON report, and `summary.ignored`), and no longer count as failures. A lowered threshold, an exception that names nothing, and an exception that names only checks that pass each give a warning. `schema/config-v1.schema.json`, published with the package, gives completion in VS Code. The JSON report gains `config` and `thresholds` for each theme, in format 1 ([#17](https://github.com/mickaellherminez/vscode-theme-audit/issues/17)).
- The command audits a packaged extension, `vscode-theme-audit my-theme-1.2.3.vsix`, and an extension of Open VSX, `vscode-theme-audit open-vsx:publisher.name[@version]`, downloaded through the public API of Open VSX and checked against the SHA-256 it publishes. A `.vsix` is extracted as VS Code installs it, into a temporary folder deleted at the end, with limits against broken or hostile archives (10,000 entries, 200 MB). The report names these themes by the `.vsix` or the id, then their path inside it. The API gives `auditInputs()`, `extractVsix()` and `downloadOpenVsx()`. The Visual Studio Marketplace is not supported: its download API is not documented ([#16](https://github.com/mickaellherminez/vscode-theme-audit/issues/16)).

### Changed
- `main()` is now asynchronous: it resolves to the exit code. yauzl, the zip library of VS Code, is now a dependency of the package ([#16](https://github.com/mickaellherminez/vscode-theme-audit/issues/16)).

## [0.1.2] - 2026-11-23

### Added
- A check of the published package: after each release, `.github/workflows/published.yml` installs the new version from npm with npx, in an empty folder, on Linux, Windows and macOS with Node.js 22 and 24, and audits the 48 themes of 365 Day & Night with it. It also runs by hand on any version. The README shows the npm version badge ([#15](https://github.com/mickaellherminez/vscode-theme-audit/issues/15)).
- The CI runs the checks and the corpus test on Linux, Windows and macOS, with Node.js 22 and 24. `npm run test:package` checks the content of the package that npm publishes (the compiled code, the JSON schema, README, LICENSE, CHANGELOG and THIRD-PARTY-NOTICES) and its size: 120 kB at most, 500 kB unpacked; `npm run check` runs it too. The package now contains the CHANGELOG ([#14](https://github.com/mickaellherminez/vscode-theme-audit/issues/14)).

### Fixed
- On Windows, a theme file whose name differs only by case was read without its warning when its path went through a short 8.3 folder name, such as the temporary folder (`C:\Users\RUNNER~1\...`): the check of the names stopped there. Such a name is now kept and the next names are still checked ([#14](https://github.com/mickaellherminez/vscode-theme-audit/issues/14)).

## [0.1.1] - 2026-11-22

### Changed
- Published with npm trusted publishing only (OpenID Connect from the release workflow, no token), with its provenance. 0.1.0 was published once with a short-lived token, since npm configures trusted publishing only for a package that exists. The code of the package does not change; the README shows the new version in its examples ([#13](https://github.com/mickaellherminez/vscode-theme-audit/issues/13)).

## [0.1.0] - 2026-11-22

### Added
- Releases from GitHub Actions: pushing a version tag (`v0.1.0`) runs `.github/workflows/release.yml`, which checks that the tag is on `main` and matches `package.json`, runs `npm run check`, publishes to npm with trusted publishing (OpenID Connect, no stored token) and provenance, then creates the GitHub release with the notes of this CHANGELOG (`scripts/release-notes.ts`). `package.json` is no longer private, with `publishConfig` for a public package with provenance. The steps, the first version and how to go back are in CONTRIBUTING ([#13](https://github.com/mickaellherminez/vscode-theme-audit/issues/13)).
- Documentation for theme authors: the README gives every way to run the command (`npx`, a global install, a project dependency, the API), its options and exit codes, how to read the text report, a GitHub Actions job, the limits and how to uninstall it or remove it from a CI. `docs/checks.md` lists every check with its keys, its minimum and its references (WCAG 2.2, CIEDE2000, Machado 2009, Brettel 1997, Viénot 1999), and `docs/report-format.md` describes the JSON report field by field, with an example ([#12](https://github.com/mickaellherminez/vscode-theme-audit/issues/12)).
- A check of the token colors in the editor of VS Code itself: `scripts/vscode-inspect.ts` opens code samples in VS Code (TypeScript, Python, JSON with comments, Markdown), clicks each token, and records what the widget *Developer: Inspect Editor Tokens and Scopes* shows and the style of the text on screen. `test/corpus/inspect.test.ts`, part of `npm run test:corpus`, gives these TextMate scopes and semantic tokens to the package, which must find the same color and font style. Five themes of the corpus (dark, light and high contrast, with and without semantic highlighting) with VS Code 1.147.0: 1,556 distinct tokens, 0 difference. `scripts/vscode-run.ts` holds what this script and `scripts/vscode-oracle.ts` share ([#11](https://github.com/mickaellherminez/vscode-theme-audit/issues/11)).
- A corpus test on real themes: the 20 most downloaded extensions of the Themes category of Open VSX on 20 November 2026, 178 theme files, at fixed versions with the SHA-256 of each `.vsix` (`test/corpus/extensions.json`). `npm run corpus` downloads them into a cache that is not committed; `npm run test:corpus` extracts them as VS Code installs them, with yauzl, audits them in both modes, and checks their themes and warnings against `test/corpus/expected.json`. The CI runs it with a cache. `node scripts/corpus.ts --update <id>@<version>` moves an extension to another version. A theme file or an `include` whose path differs from the file name only by case is now read on every system, with a warning, since VS Code finds it on macOS and Windows but not on Linux ([#10](https://github.com/mickaellherminez/vscode-theme-audit/issues/10)).
- The command audits theme files and extension folders: `vscode-theme-audit <theme file or extension folder>...`. A text report gives each failed check with its colors, the value measured and the minimum, the pairs of colors that a vision confuses, and a summary. `--json` prints the report as JSON for CI, in format 1, described by `schema/report-v1.schema.json`, published with the package. `--strict` applies the rules of 365 Day & Night. Exit codes: `0` when every check passes, `1` when a check fails, `2` when a theme cannot be read or the command is misused. A theme file takes its type and name from the extension that declares it, or from its `type` field ([#9](https://github.com/mickaellherminez/vscode-theme-audit/issues/9)).
- The checks of the audit, ported from `audit.py` and `variety.py` of 365 Day & Night: WCAG 2.2 contrast of the text and of each syntax and semantic color on its backgrounds (7:1 in high contrast themes), the styles of WCAG 1.4.1, the colors that must stay distinct with color blindness (CIEDE2000 of at least 7 with every model), and achromatopsia for information. By default they read the colors that VS Code shows, defaults included: a missing color is information, the text of the terminal is measured after the minimum contrast of VS Code (computed as xterm.js does), the main text needs 4.5:1 (7:1 in high contrast), and the styles are information. The strict mode applies the rules of 365 Day & Night: colors set by the theme only, 7:1 for the main text, the styles required, the terminal measured with the colors of the theme, required keys and semantic rules, the status bar button, and the variety between the themes of one type. In strict mode, the 48 themes of 365 Day & Night give the same results as `audit.py` and `variety.py`: 13,212 checks, 7,104 pairs and the variety of 4 variants, to 0.01 ([#8](https://github.com/mickaellherminez/vscode-theme-audit/issues/8)).
- The workbench colors of a theme as VS Code shows them, with the defaults of VS Code for the keys the theme leaves out, for the four theme types, and where each color comes from: the theme, a default of VS Code, or derived from other keys, which are listed. The 1,007 defaults of VS Code 1.147.0 are extracted from its sources by `scripts/vscode-colors.ts`, with the colors of its built-in Git extension; the transforms of VS Code (transparent, opacity, darken, lighten, opaque, mix, one of, less prominent, if defined then else) and its `Color` are ported with their tests. The colors that an extension contributes (`contributes.colors`) are read too. A missing key is information; a strict mode makes it a failure, as in the audit of 365 Day & Night. Checked against VS Code itself with `scripts/vscode-oracle.ts`: 0 difference on 226,726 colors of 226 themes with VS Code 1.146.0, and a sample of 251 keys of four test themes in the tests ([#7](https://github.com/mickaellherminez/vscode-theme-audit/issues/7)).
- The style of a semantic token, as VS Code shows it when a theme sets `semanticHighlighting`: the rules of `semanticTokenColors` (type, modifiers and language, the best score winning for each property), then the TextMate scopes that VS Code probes for each token type, including those of its built-in JavaScript and TypeScript extensions. Ported from VS Code with its tests. Loading a theme now warns about semantic colors that VS Code cannot read, and refuses a theme that VS Code refuses ([#6](https://github.com/mickaellherminez/vscode-theme-audit/issues/6)).
- The style of a token from its scopes, as VS Code shows it with TextMate grammars: the matching of vscode-textmate (scope prefixes, comma-separated selectors, parent scopes and `>`, the most specific rule wins), ported with its tests, and the rules that VS Code gives it (the editor colors as defaults, colors written in full, log colors). Checked against vscode-textmate itself, on random themes in the tests and on 11,036 styles of the 178 themes of the corpus, with no difference.
- Reading a color theme the way VS Code does: JSON with comments and trailing commas, `include`, `"default"` to remove an included color, the old `settings` format, `semanticTokenColors`, and the themes of an extension folder with their `uiTheme` and translated labels. Warnings for what VS Code accepts but probably was not meant, such as a color it shows in red. TextMate theme files (`.tmTheme`) are not supported yet.
- The measuring tools, ported from `colorlib.py` of 365 Day & Night with the same results: WCAG 2 contrast, alpha compositing, CIELAB, CIE76 and CIEDE2000, and the color blindness simulations of Machado et al. 2009, Brettel et al. 1997 and Viénot et al. 1999, with the models kept for each deficiency. Tested against published data (Sharma et al. 2005, Machado et al. 2009), DaltonLens, and the results of `colorlib.py`.
- The package and its command, with `--help` and `--version`. TypeScript run directly by Node.js 22.18 or later, ESLint, tests with the test runner of Node.js, CI on Node.js 22 and 24, and CodeQL ([365-daynight-vscode-theme-ext#100](https://github.com/mickaellherminez/365-daynight-vscode-theme-ext/issues/100)).
